### R12-H2 — Grafana + MLflow containers run as root end-to-end
`docker/Dockerfile.grafana:12` and `docker/Dockerfile.mlflow:21` set `USER root`;
both entrypoints (`grafana_entrypoint.sh:60` → `exec /run.sh`,
`mlflow_entrypoint.sh:113` → `exec mlflow`) exec the service **without dropping
privileges**. MLflow additionally `pip install`s as root at build. Both hold
Lockbox-fetched secrets. Same class as open #65 hardening — fold in: root-phase
secret fetch, then drop to the service UID (grafana 472, dedicated mlflow user)
before exec.

### R12-H3 — telegram.py robustness triple (verified by hand)
1. `consume_link_token` (`src/notifications/telegram.py:223-236`): `r.get` then
   `r.delete` — non-atomic; concurrent `/start` double-consumes a one-shot link
   token. Fix: Redis `GETDEL` (redis-py ≥4.2) — one line.
2. `send_message` (`:78-103`): single attempt, swallow→False, no retry — a
   transient blip silently loses a training-complete notification (backup.sh
   already has the 3-attempt pattern to copy). NB: Alertmanager-routed alerts
   are NOT affected (Alertmanager retries internally).
3. `handle_update` (`:410-425`): read-modify-write of the whole client `config`
   JSON → last-write-wins; a concurrent settings save can clobber the telegram
   link (or vice versa). Fix: registry-level partial/JSONB update for the
   `notifications.telegram` subtree.

### R12-H4 — CD pulls images without cosign verification
`cd.yml:168-181` signs images keylessly; `scripts/cd_deploy.sh:190-202` pulls
and runs them with **no `cosign verify`** — signing effort is currently
write-only. Verify digest signature (certificate-identity-regexp on the repo,
GitHub OIDC issuer) before `docker pull`/`up`, fail-closed.

## 5. Forecast-quality improvement plan (grounded)

Priority order, each grounded in code observation:
1. **#58 sku_encoded skew** (KNOWN, top item): serve re-factorizes a single SKU
   → code 0 always (`engineering.py:96` + inference path). Fix = persist the
   train-time mapping in the model artifact, or drop the feature. Likely the
   single largest serve-quality lever currently open.
2. **Known-future covariates**: compute holidays + calendar for TARGET dates in
   both serve paths (R12-M4 fixes recursive; for direct/MIMO this is the
   "third path" — direct + target-date calendar — which the #59 A/B hinted at:
   recursive h1 0.184 beat direct h1 0.216 purely on target-date calendar).
   Requires train-side change (feed future covariates per head), so gate it
   through the same-model A/B harness.
3. **Ensemble blend weights on a clean holdout** (`ensemble.py:112-132`
   documents the v1 seen-data shortcut, ~33% train-time cost to fix) — paid
   tiers only.
4. **Per-SKU scale normalization** — global model over demand ranges spanning
   orders of magnitude; z-score per SKU with inverse at serve.
5. **Feature-importance logging to MLflow** (forecaster has it computed,
   never persisted; MIMO/Ensemble lack it) — visibility to kill dead features
   (weather? FX regressors?) and justify HPO budget.
6. **Horizon alignment**: model horizon (14) vs plan horizons (30/90) — far
   horizons currently always fall back to recursion; decide per-tier model_h.
7. #59 default-direct decision: pending Business-tier same-model A/B (ensemble
   far heads are stronger; direct may win there → tier-gate the dispatch).

All serve-path changes MUST go through `scripts/backtest_ab_serve.py`
(same-model A/B) per the confounded-comparison lesson.
