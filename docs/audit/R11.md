## Method

Fresh independent sweep — does NOT inherit R9/R10 findings (those are cross-referenced only when a finding overlaps). **Fact-only rule:** every finding is verified against the actual code, never trusting comments / docstrings / annotations. Sweep agents over-report → every HIGH/CRIT is adversarially re-read against the real code before it lands here ([[feedback_audit_agent_verification]]).

Severity: **CRIT** (exploitable / data-loss / prod-down) · **HIGH** (security or correctness, realistic trigger) · **MED** (correctness/quality, bounded blast radius) · **LOW** (hygiene) · **INFO** (note).

Status per finding: `UNVERIFIED` (agent-reported, not yet re-read) → `CONFIRMED` (re-read against real code) / `REJECTED` (false positive) → `FIXED` (PR merged + verified).

### HIGH

**H1 [V] — `sku_encoded` train/serve skew: every served SKU presents code 0.**
`src/features/engineering.py:96` runs `df["sku_encoded"] = pd.factorize(df[sku_col])[0]` at the top level of `build_features` (not inside the per-SKU groupby at :55-65). `get_feature_columns` (:202-218) keeps `sku_encoded` in the model's feature set. Train (`train.py:155`) calls `build_features` on the FULL multi-SKU catalog → `sku_encoded ∈ {0..N-1}`; the global model (fit with `groups=df[sku_col]`, train.py:232) learns splits on it. Serve (`inference.py:411`) calls `build_features` on a SINGLE-SKU frame → `pd.factorize` → `sku_encoded = 0` for every SKU. **Train/serve skew on a model feature, affecting 100% of `/predict` calls.** Lag/rolling/calendar features remain correct (SKU's own history), so it's degradation not garbage — magnitude = LightGBM's importance weight on `sku_encoded` (needs a backtest to quantify). Fix: persist the train-time sku→code map and apply at serve, or drop `sku_encoded` (it's a meaningless nominal-as-ordinal feature anyway).

**H2 [V] — MIMO/Ensemble (direct multi-step) models are served recursively using only the h=1 head.**
Default config is `type: mimo` (`configs/config.yaml:51`). `inference.py:430` calls `recursive_forecast(...)` **unconditionally** — grep confirms NO `is_mimo`/`is_ensemble`/`predict_next` branch anywhere in the serve path. `inference_utils.py:242` takes `raw.flat[0]` (the h=1 element) then feeds it back as `lag_1` and re-predicts h=1 for each step. A MIMO model trains H independent heads specifically to avoid recursion's compounding error (mimo.py docstring); at serve, heads 2..H are never used and the forecast suffers the exact error accumulation the architecture exists to eliminate. Fix: branch on `is_mimo`/`is_ensemble` and call the direct `(H,)` predict once; reserve `recursive_forecast` for the single-step `lgbm` model.

**H3 [V] — SKU plan cap bypassable (unreadable manifest → 0 → skip; legacy data_path route → never checked).**
`training.py:137` evaluates the SKU cap ONLY `if req.upload_id`. The manifest read (`:156-160`) falls to `sku_count = 0` on any exception, and `:161 if sku_count > 0` then skips `assert_sku_count_within_limit` — the ONLY enforcement of `max_skus`. A no-`upload_id` `data_path` training (`:177`) skips the cap entirely. A Free/Start client can train beyond their `max_skus` (quota/billing integrity). Fix: treat an unreadable manifest as a hard error; enforce the cap on resolved row count when no upload_id.

**H4 [V] — Concurrent training runs clobber model artifacts (no in-flight guard).**
The atomic quota gate (`record_training_started`, training.py:226) enforces the monthly COUNT cap but is a no-op for Business (`training_runs_per_month=UNLIMITED`, `training_cooldown_hours=UNLIMITED`, plans.py:164-167) and doesn't bound concurrency for Start (cooldown=UNLIMITED). `registry.update(status="training")` (training.py:230) is non-atomic with the gate and there is NO `status != 'training'` check before enqueue. Two concurrent `POST /train` both pass → both run `run_training_pipeline` → both write the fixed per-client key `{client_id}/models/model.pkl` (`storage/backend.py`) and both `DELETE+INSERT` forecasts → a half-written model served by `/predict`, or served model and served forecasts from different runs. Fix: gate enqueue on `status != 'training'` in the same row-locked conditional UPDATE, or write run-scoped keys + atomic promote.

**H5 [A] — `/jobs/{job_id}` leaks the full worker traceback to the tenant.**
`src/pipeline/task_queue.py:824` returns `"error": str(job.exc_info)` (RQ's full formatted Python traceback — file paths, lib versions, sometimes data/DSN fragments in the message); `src/api/routers/training.py:342-347` returns it to the caller. The `except` branch additionally returns `str(e)`. Every other handler funnels exceptions to a `trace_id` (inference.py:457-469); this one bypasses it. Fix: generic message + logged trace_id, keep `exc_info` server-side.

**H6 [A] — `aggregate_metrics` raises IndexError when all per-SKU metrics are NaN.**
`src/validation/metrics.py:109-112`: `np.percentile(vals, 90)` on an empty array (after `dropna()`) raises `IndexError`. An all-zero-sales catalog (or a fold where every SKU has `sum(actual)==0`) makes wmape/smape/mase all NaN → training run dies with an opaque error instead of reporting "no measurable demand". Fix: guard `len(vals)==0` → emit NaN.

**H7 [V] — `/readyz` emits structurally invalid JSON (+ `/readyz` leaks dependency-failure class).**
`src/api/routers/ops.py:158-162`: `str({"ready": overall_ok, "checks": checks}).replace("'", '"')` renders Python literals — `False`/`None` are not valid JSON (I observed `{"ready": True, ...}` live on prod during this session). Any LB/orchestrator parsing the body gets a parse error precisely in the failure case. Separately (`:142,151`), the unauthenticated probe returns `type(e).__name__` (e.g. `OperationalError`) — infra info disclosure. (= roadmap T2.) Fix: `JSONResponse({...}, status_code=...)` + drop the error-class from the public body.

**H8 [A] — App + data tier containers have no `cap_drop`/`no-new-privileges`/`read_only`.**
`docker-compose.yml` api (:136), worker (:177), scan-worker (:209), process-worker (:253), postgres (:383), mlflow (:592) have resource limits + healthchecks but NO capability dropping or privilege-escalation block — only pgbouncer/autoheal/docker-socket-proxy got the hardening. Every Python service runs with the full default cap set + `allowPrivilegeEscalation`. Fix: add `cap_drop:[ALL]` + `security_opt:[no-new-privileges:true]` to the app/data tier.

**H9 [A] — `process-worker` mounts the raw Docker socket read-write with no privilege hardening.**
`docker-compose.yml:270-272` (+ minimal.yml:43-44, the live path): `/var/run/docker.sock:/var/run/docker.sock` (RW, not `:ro`), no `cap_drop`, no `no-new-privileges`, on the worker that by design parses UNTRUSTED customer uploads. Full RW docker.sock = host root. The codebase already solved this exact risk for autoheal via `docker-socket-proxy`; process-worker still has the unrestricted socket — the single largest blast-radius surface in the stack. Fix: scope it behind a least-privilege socket proxy (allow only `containers/create+start` with an image/flag allowlist) or a rootless/sysbox runtime; at minimum add `no-new-privileges`.

- **M3 [A] JWT revocation doesn't propagate across workers/containers during a Redis outage** — `jwt_auth.py:323-357` writes to per-process `_inmem_revoked` + fails open on Redis read error. Logout unreliable during a Redis blip, bounded by 1h exp. Fix: shorter access-token TTL or DB-backed revocation fallback.
- **M4 [A] `/readyz` batch-predict: `return_exceptions=False` sinks the whole batch on one bad SKU + N× rate-limit accounting** — `inference.py:507`. Fix: `return_exceptions=True` + per-item results.
- **M5 [A] Anomalies/forecasts replace aborts on duplicate `(sku,date)`** — `storage/anomalies.py:59-71` INSERT has no `ON CONFLICT` but PK forbids dup (`migrations/004:12`); multi-warehouse uploads with dup (sku,date) → UniqueViolation → whole DELETE+INSERT rolls back → client keeps PREVIOUS run's anomalies, silently stale (caller swallows to a warning). Same shape in `forecasts.py:79-93`. Fix: `ON CONFLICT … DO UPDATE` + dedup upstream.
- **M6 [A] `/forecasts` full-table read, no LIMIT/pagination** — `storage/forecasts.py:102-131` (every sibling registry caps); ~45k rows on Start, unbounded on Business, serialized on the event loop. Fix: LIMIT + pagination.
- **M7 [V] train.py MLflow temp pkl leaks on failure** — `pipeline/train.py:292-302`: the `unlink` is outside the `with` and after a save/log that can raise; the `except` skips it. Every failed-MLflow training leaks a model-sized `/tmp/*.pkl`. Fix: `try/finally` + `unlink(missing_ok=True)`.
- **M8 [A] Merged-dataset temp parquet leaks on incremental-retrain failure** — `pipeline/task_queue.py:399-418`: `_cleanup_merged` is the last linear step, skipped if training raises. Fix: move cleanup to `finally`.
- **M9 [A] ClusterBasedForecaster returns a StandardScaler z-score as the forecast** — `models/cold_start.py:82-84,119`: `mean_sales` is overwritten by `fit_transform` then returned as the forecast (≈0/negative). LATENT (`cluster.predict` not yet wired to `/predict`) → garbage the moment cold-start routing is enabled. Fix: keep an unscaled `mean_sales`.
- **M10 [A] `with_fallback` masks total model failure by returning all-zeros tagged "zero"** (default `raise_if_both_fail=False` on the serving path) + shape divergence primary `(N,H)` vs fallback `(N,)` — `models/fallback.py:117-121,162`. Fix: default raise on serving path; normalize shape.
- **M11 [A] SeasonalNaive `fit` on empty/all-NaN series fills the season with NaN** — `models/fallback.py:73-79` (`np.mean([])→nan`); NaN reaches `/predict` response via the non-clipped `predict()`. Fix: guard empty/all-NaN → 0.0 + `nan_to_num`.
- **M12 [A] cAdvisor runs `privileged: true`** — `docker-compose.yml:1108` (needs only `cap_add:[SYS_PTRACE]` + `/dev/kmsg`). Host-wide blast radius on a cAdvisor CVE. Fix: drop privileged.
- **M13 [A] Custom-image Dockerfile `FROM` lines not digest-pinned** — `python:3.11-slim`, `postgres:16-alpine`, `nginx:1.27-alpine`, `prom/alertmanager:v0.28.1`, `postgres-exporter:v0.15.0` (compose `image:` were R4-20 digest-pinned; the Dockerfile bases were missed). - **M14 [A] `migrate` one-shot has no `mem_limit`/`cpus`** — `docker-compose.yml:116-127` (escaped the R5-M9 sweep). Fix: add limits.
