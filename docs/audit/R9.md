## Cross-track patterns (the systemic findings)

These are not single bugs — they are *patterns* the prior audits could not see because each audit looked at one layer in isolation.

### Pattern 1: Exception-swallow leading to fail-open (R8-12 class)

Found at 9 sites across 5 modules. Same shape every time: `try / except Exception: logger.warning(...) / return None`. Caller treats `None` as "no error", so the failure becomes invisible.

| Site | File | Line | Severity |
|---|---|---|---|
| MLflow log_artifact | `src/pipeline/train.py` | 301–302 | **CRIT (R8-12)** |
| MLflow log_artifact (root) | `src/pipeline/train.py` (forecaster) | 166 | **CRIT (R8-12)** |
| Post-training forecast | `src/pipeline/train.py` (`_generate_and_store_forecasts`) | tba | **CRIT (T7-002)** |
| Training fallback registry | `src/pipeline/task_queue.py` | 737–751 | **HIGH (T4-001)** |
| JWT revocation cleanup | `src/auth/jwt_auth.py` | 370–376 | MED (T4-005) |
| Audit DB replica fallback | `src/audit/log.py` | 186, 220 | MED (T4-004) |
| Telegram offset load | `src/notifications/telegram.py` | 42–52 | MED (T2-006) |
| API key hash try | `src/auth/api_keys.py` | 145–151 | MED (T4-006) |
| Upload error message | upload worker | tba | LOW (T7-010) |

**Class fix**: project-wide lint rule (`bandit` or custom AST check) flagging any `except Exception:` inside a function with a non-None return value. Combined with a code-review checkpoint: every catch must either re-raise, persist an error record, or emit an audit event.

### Pattern 2: Healthcheck-vs-data-integrity gap

## R8-12 family — consolidated view

R8-12 turned out to be the visible tip of a multi-layer failure. Track-7 prod inspection revealed the full picture:

| Layer | Finding | Site |
|---|---|---|
| Architecture | Worker has no `/mlflow` mount; `--default-artifact-root /mlflow/artifacts` is a local path that only the server can write to | `docker-compose.minimal.yml:31–37` |
| Transport | `--allowed-hosts` missing `localhost:5000` / `127.0.0.1:5000` → 403 DNS-rebinding rejection on intra-container calls | mlflow command-line |
| Exception handling | Worker catches `[Errno 13] Permission denied: '/mlflow'` as WARNING, returns `run_id=None`, pipeline persists `mlflow_run_id=NULL` and marks status `finished` | `src/pipeline/train.py:301–302` |
| Persistence | `sku_training_runs.mlflow_run_id` and `sku_clients.last_mlflow_run_id` both NULL across the board | DB |
| Observability | MLflow `/health` returns 200 throughout; `docker ps` shows healthy; no Prometheus alert on `mlflow_run_id IS NULL` ratio | infra |
| Forecast persistence (cousin) | Latest finished run produced 0 forecast rows because post-training inference path has a different feature set than training; KeyError silently swallowed | `src/pipeline/train.py:_generate_and_store_forecasts` |

**Fix architecture (B′ from prior session — still valid)**: proxied artifacts → S3 backing store. `mlflow server --serve-artifacts --artifacts-destination s3://<bucket>/mlflow/ --default-artifact-root mlflow-artifacts:/`. Worker uses `mlflow-artifacts://` scheme → HTTP PUT to mlflow:5000; MLflow container does the S3 PUT itself via Lockbox-fetched creds. Same pattern as backup/alertmanager. Plus: re-raise the swallowed exception so failed runs land as `status='failed'`. Plus: SQL invariant exporter + alert. Plus: synthetic smoke probe at deploy time.

Cousin fix (T7-002): align training-time and post-training-inference-time feature sets via a single FeatureBuilder; mark run `finished_with_warnings` + persist `error` column when forecast generation fails; add invariant alert `count(status='finished' AND run_id NOT IN sku_forecasts) > 0`.
