# Sprosly API — публичная документация

Sprosly — B2B-сервис прогнозирования спроса и автозаказа. Этот документ описывает
публичный HTTP API для интеграций: загрузка данных о продажах, управление датасетами,
запуск обучения модели, чтение прогнозов и выгрузка рекомендаций к заказу (в т.ч. CSV для 1С).

- Справочник эндпоинтов: [endpoints.md](endpoints.md)
- Сквозные сценарии (curl-скрипты): [examples.md](examples.md)

## Базовый URL

```
https://api.sprosly.com
```

Все запросы — только по HTTPS (HTTP отвечает редиректом 301). Тела запросов и ответов — JSON
(`Content-Type: application/json`), кроме загрузки файлов (`multipart/form-data`) и
CSV-выгрузки рекомендаций.

## Аутентификация

Поддерживается один рабочий механизм для интеграций: **JWT Bearer-токен**,
полученный обменом персонального API-ключа.

### 1. API-ключ

Каждому клиенту (workspace) принадлежит персональный API-ключ формата:

```
sku_<43 символа base64url>
```

Ключ показывается **один раз** в момент выпуска и хранится на сервере только в виде
bcrypt-хеша. Выпуск нового ключа (и отзыв старого):

```bash
curl -s -X POST "https://api.sprosly.com/clients/$CLIENT_ID/api-key/rotate" \
  -H "Authorization: Bearer $TOKEN"
# → {"client_id": "...", "api_key": "sku_...", "warning": "Сохраните новый api_key. Старый теперь недействителен."}
```

Ротация доступна не чаще 5 раз в час на клиента. Уже выданные JWT продолжают
действовать до истечения своего срока (по умолчанию 60 минут).

### 2. Обмен ключа на токен

`POST /auth/token` принимает `client_id` + секрет и возвращает JWT:

```bash
TOKEN=$(curl -s -X POST https://api.sprosly.com/auth/token \
  -H "Content-Type: application/json" \
  -d '{"client_id": "my-shop", "secret": "sku_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX"}' \
  | jq -r .access_token)
```

Ответ:

```json
{"access_token": "eyJhbGciOiJIUzI1NiIs...", "token_type": "bearer"}
```

### 3. Использование токена

Токен передаётся в каждом запросе в заголовке `Authorization`:

```bash
curl -s "https://api.sprosly.com/clients/my-shop/usage" \
  -H "Authorization: Bearer $TOKEN"
```

Свойства токена:

- срок жизни — **60 минут** (по истечении — 401, обменяйте ключ на новый токен);
- `POST /auth/logout` (204) отзывает текущий токен досрочно;
- токен даёт доступ **только к данным своего клиента**: обращение к чужому
  `client_id` возвращает 403, к чужим ресурсам по id (upload, датасет, job) — 404
  (существование чужих ресурсов не раскрывается).

### Вход по паролю (веб-кабинет)

`POST /auth/login/password` (email + пароль) тоже возвращает `access_token` и
дополнительно ставит httpOnly refresh-куку для `POST /auth/refresh`. Этот флоу
рассчитан на браузерный кабинет: после 2 неудачных попыток включается captcha
(Cloudflare Turnstile), а refresh-механизм работает через куки. Для серверных
интеграций используйте `/auth/token` с API-ключом.

## Формат ошибок

Единый контракт для всех эндпоинтов:

| Случай | Тело ответа |
|---|---|
| Ошибка приложения (4xx/5xx) | `{"detail": "<строка>"}` — иногда `detail` содержит структурированный объект (см. ниже) |
| Ошибка валидации (422) | `{"detail": [<список pydantic: loc/msg/type>], "message": "<готовая строка>"}` |
| Необработанная ошибка (500) | `{"detail": "internal error (trace_id=<id>)"}` |

- Каждый ответ несёт заголовок `X-Request-ID` (можно задать свой в запросе,
  до 64 символов) — указывайте его при обращении в поддержку.
- Ответы 429 несут заголовок `Retry-After` (в секундах).

### Отказ в обучении (429/409): структурированный `detail`

Эндпоинты запуска обучения при отказе возвращают в `detail` машиночитаемый конверт:

```json
{
  "reason_code": "cooldown",
  "message": "Training cooldown active on plan 'free'. Next training allowed in ~11.5h (at 2026-07-18T09:00:00+00:00).",
  "retry_after_sec": 41400,
  "cooldown_until": "2026-07-18T09:00:00+00:00"
}
```

Стабильные значения `reason_code`:

| Код | HTTP | Значение |
|---|---|---|
| `cooldown` | 429 | действует пауза между обучениями (тариф Free — 12 ч) |
| `in_flight` | 409 | у клиента уже идёт обучение (1 одновременное на клиента, все тарифы) |
| `lost_race` | 429 | проигрыш гонки за слот при конкурентных запросах — повторите через секунду |

## Лимиты

### Сетевые (per IP)

| Зона | Лимит | Всплеск (burst) |
|---|---|---|
| `POST /auth/token` | 10 запросов/мин | +5 |
| `POST /clients/{id}/uploads` | 20 запросов/мин | +10 |
| Все остальные эндпоинты | 600 запросов/мин | +100 |

### Прикладные

| Что | Лимит |
|---|---|
| `POST /auth/token` | 20/час на /24-подсеть |
| `POST /clients/{id}/api-key/rotate` | 5/час на клиента |
| `POST /clients/{id}/predict` и `/predict/batch` (суммарно; batch из N позиций = N запросов) | по тарифу: Free 100/час, Start 5000/час, Business — без лимита |
| Размер загружаемого файла | 50 МБ |

### Тарифные лимиты

| Тариф | Модель | SKU | Горизонт прогноза | Пауза между обучениями | Датасеты |
|---|---|---|---|---|---|
| Free | Notus | 30 | 7 дней | 12 ч | 1 |
| Start | Aether | 1500 | 30 дней | — | 3 |
| Business | Chronos | без лимита | 90 дней | — | 10 |

Актуальные значения всегда доступны без авторизации: `GET /plans`; ваши текущие
лимиты и статус паузы — `GET /clients/{id}/usage`. Запрошенный горизонт прогноза
сверх тарифного не отклоняется, а **обрезается** до потолка (в ответе `/predict`
это видно по `horizon_limited_by_plan: true`).

## Версионирование и стабильность

- Версионного префикса в путях **нет** (`/clients/...`, не `/v1/clients/...`).
- Изменения расширяющие (новые поля в ответах, новые эндпоинты) выпускаются без
  предупреждения — не полагайтесь на точный набор полей, игнорируйте незнакомые.
- Формальная политика обратной совместимости пока не опубликована (см.
  «Открытые вопросы» в [endpoints.md](endpoints.md)).

## Типовой цикл интеграции

1. Загрузить CSV/XLSX с историей продаж → `POST /clients/{id}/uploads` (со `dataset_id`).
2. Дождаться антивирусной проверки (`scanned_clean`), запустить подготовку →
   `POST /clients/{id}/uploads/{upload_id}/prepare`, дождаться `processed`.
3. Запустить обучение → `POST /clients/{id}/datasets/{dataset_id}/train`.
4. Поллить `GET /jobs/{job_id}` до `finished`, метрики — в `GET /clients/{id}/training-runs`.
5. Читать прогнозы (`GET /clients/{id}/forecasts`) и рекомендации к заказу
   (`GET /clients/{id}/order-recommendations`, `format=csv` — выгрузка для 1С).

Готовые скрипты этих сценариев — в [examples.md](examples.md).

## Требования к данным

- Форматы файлов: `.csv`, `.xlsx` (`.xls` не поддерживается — пересохраните как `.xlsx`).
- Колонки распознаются автоматически (кодировка, разделитель, соответствие колонок);
  канонические поля: `date` (дата), `sku` (артикул), `sales` (продажи, шт.),
  опционально `price`, `promo`, `stock`.
- Минимум 30 строк истории на SKU для прогноза.
