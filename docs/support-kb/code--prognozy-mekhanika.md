# Как устроены прогнозы: автоматический расчёт после обучения, минимум истории, лимиты запросов

## Прогнозы считаются автоматически

После каждого успешного обучения сервис сам рассчитывает прогноз по **всем SKU** датасета — ничего дополнительно запускать не нужно, раздел «Прогнозы» просто показывает готовый результат. По каждому товару и дню доступны точечное значение и диапазон p10–p90; для автозаказа — рекомендуемое количество.

## Минимум истории на товар

Для построения прогноза по конкретному SKU нужно **не меньше 30 дней истории** этого товара. По товарам с меньшей историей точечный прогноз через API вернёт ошибку с указанием количества имеющихся строк. Накапливайте историю и добавляйте такие товары позже.

## Горизонт и тариф

Горизонт прогноза ограничен тарифом (Free — 7 дней, Start — 14, Business — 28). Если запрошен больший горизонт, он автоматически уменьшается до лимита, и в ответе появляется пометка «горизонт ограничен тарифом».

## Прогноз через API

Для интеграций доступен программный доступ по API-ключу (создаётся в Настройках). Запрос прогноза принимает SKU и историю продаж (или ссылку на загруженные данные) и возвращает прогноз по дням с указанием использованной модели (Notus / Aether / Chronos). Есть пакетный режим — до 100 запросов за раз; результаты возвращаются по каждому элементу независимо: ошибка по одному товару не отменяет прогнозы остальных.

Лимиты запросов прогноза: Free — 100 в час, Start — 5 000 в час, Business — без ограничений. При превышении лимита придёт ответ с кодом 429 и временем, через которое можно повторить.

## Если модель недоступна

Если основная модель по какой-то причине не смогла построить прогноз, сервис вернёт резервный прогноз на основе сезонности (в ответе API это помечено полем model_source = fallback), чтобы вы не остались без числа. Такие случаи — сигнал переобучить модель.
