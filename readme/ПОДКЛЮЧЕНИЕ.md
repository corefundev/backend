## 1. Архитектура

```
VPS-1 (Backend)          VPS-2 (Frontend)
┌─────────────────┐      ┌─────────────────┐
│  FastAPI :8000  │◄─────│  Nginx :80/443  │
│  Redis :6379    │      │  React SPA      │
│  PostgreSQL     │      └─────────────────┘
│  S3 / local     │
└─────────────────┘
```

Фронтенд — статичный React SPA. Все API-запросы идут напрямую с браузера на бэкенд (CORS).

Файл `.env` в корне фронтенда (рядом с `vite.config.ts`):


После изменения `.env`:
```bash

```

## 3. CORS на бэкенде

**Это обязательно!** Без CORS браузер заблокирует все запросы.

Добавьте в `src/api/main.py` ПОСЛЕ строки `app = FastAPI(...)`:

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=[
        "https://app.yourdomain.com",   # ваш фронтенд домен
        "http://localhost:3000",         # локальная разработка
    ],
    allow_credentials=True,
    allow_methods=["GET", "POST", "PUT", "PATCH", "DELETE", "OPTIONS"],
    allow_headers=["*"],
)
```

Перезапустите бэкенд после изменений:
```bash
docker compose restart api
```

## 4. Авторизация: как работает JWT

### Как устроена auth

```
Браузер                   Backend FastAPI
  │                            │
  │  POST /auth/token          │
  │  { client_id, secret }     │
  │ ─────────────────────────► │
  │                            │  secret == API_KEY из .env бэкенда
  │  { access_token, type }    │  JWT содержит: client_id, roles, exp
  │ ◄───────────────────────── │
  │                            │
  │  GET /clients/{id}         │
  │  Authorization: Bearer ... │
  │ ─────────────────────────► │
  │                            │
```

### Ключевое понимание

**`secret` в форме логина = `API_KEY` из `.env` бэкенда** — это не пароль пользователя, это серверный ключ.

- Один `API_KEY` на всю систему (в `.env` бэкенда)
- Каждый клиент входит со своим `client_id` и общим `API_KEY`
- JWT кодирует `client_id` и `roles: ["forecast"]`
- Если `API_KEY` совпадает — логин успешен, роль `forecast`

### Роли в JWT

| Роль | Как получить | Доступ |
|------|--------------|--------|
| `forecast` | POST /auth/token | Только своего клиента |
| `admin` | Через API-ключ (`x-api-key: API_KEY`) | Все клиенты |

Для входа в админку используется статический API-ключ через заголовок `x-api-key`, а не JWT.

> **Для полноценного фронтенда с разными паролями** нужно добавить таблицу пользователей и свою auth логику на бэкенде — в текущей версии это не реализовано.

### JWT payload

```json
{
  "sub": "my-company",
  "client_id": "my-company",
  "roles": ["forecast"],
  "iat": 1714000000,
  "exp": 1714003600
}
```

Фронтенд декодирует через `jwtDecode` (библиотека `jwt-decode`) при логине.

## 6. Nginx конфиг

Создайте файл `/etc/nginx/sites-available/sku-frontend`:

```nginx
server {
    listen 80;
    server_name app.yourdomain.com;

    root /var/www/sku-frontend;
    index index.html;

    # SPA: все неизвестные маршруты → index.html (React Router)
    location / {
        try_files $uri $uri/ /index.html;
    }

    # Опционально: проксировать API через тот же домен (избегает CORS)
    # location /api/ {
    #     proxy_pass http://BACKEND_VPS_IP:8000/;
    #     proxy_set_header Host $host;
    #     proxy_set_header X-Real-IP $remote_addr;
    # }

    # Кэширование статики
    location ~* \.(js|css|png|jpg|ico|woff2)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # Gzip
    gzip on;
    gzip_types text/plain application/javascript application/json text/css;
}
```

```bash
sudo ln -s /etc/nginx/sites-available/sku-frontend /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

### TLS (HTTPS через Certbot)

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d app.yourdomain.com
```

## 7. Роли и доступ к эндпоинтам

| Эндпоинт | Метод | Нужна роль | Описание |
|---|---|---|---|
| `/auth/token` | POST | нет | Получить JWT |
| `/health` | GET | нет | Статус сервиса |
| `/clients/{id}` | GET | свой id или admin | Данные клиента |
| `/clients/{id}/config` | GET | свой id или admin | Конфиг (override + effective + diff) |
| `/clients/{id}/config` | PUT | свой id или admin | Заменить весь override |
| `/clients/{id}/config` | PATCH | свой id или admin | Изменить один ключ dot-notation |
| `/clients/{id}/config` | DELETE | свой id или admin | Сбросить к дефолтам |
| `/clients/{id}/train` | POST | свой id или admin | Запустить обучение |
| `/jobs/{job_id}` | GET | любой auth | Статус задания |
| `/clients/{id}/predict` | POST | свой id или admin | Прогноз |
| `/clients/{id}/predict/batch` | POST | свой id или admin | Batch прогноз (до 100) |
| `/clients/{id}/reload` | POST | свой id или admin | Перезагрузить модель из storage |
| `/clients` | GET | **admin** | Список всех клиентов |
| `/clients` | POST | **admin** | Создать клиента |
| `/system/config` | GET | **admin** | Системный конфиг (read-only) |
| `/metrics` | GET | любой auth | Prometheus метрики |

## 8. Клиентский конфиг — полная схема

Эндпоинт `GET /clients/{id}/config` возвращает три вещи:

```json
{
  "client_id": "my-company",
  "override": {
    "model": { "horizon": 28 }
  },
  "effective": {
    "model": { "horizon": 28, "type": "mimo", "n_estimators": 500, ... },
    "features": { "weather": { "enabled": false }, "holidays": { "enabled": true, "country": "RU" }, ... },
    ...
  },
  "diff": {
    "model.horizon": { "system": 14, "client": 28 }
  }
}
```

- `override` — только то что клиент изменил (дельта)
- `effective` — финальный конфиг (системный + override, deep merge)
- `diff` — какие ключи отличаются от системного дефолта

### Изменить один ключ (PATCH)

```bash
# Изменить горизонт через dot-notation
curl -X PATCH https://api.yourdomain.com/clients/my-company/config \
  -H "Authorization: Bearer TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"key": "model.horizon", "value": 28}'
```

### Включить погоду (PUT)

```bash
curl -X PUT https://api.yourdomain.com/clients/my-company/config \
  -H "Authorization: Bearer TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "config": {
      "model": { "horizon": 21 },
      "features": {
        "weather": { "enabled": true, "latitude": 55.75, "longitude": 37.62 },
        "holidays": { "country": "RU" }
      }
    }
  }'
```

### Допустимые значения (из config_manager.py)

| Ключ | Диапазон | Дефолт |
|------|----------|--------|
| `model.horizon` | 1–90 | 14 |
| `model.type` | lgbm, mimo | mimo |
| `model.n_estimators` | 50–5000 | 500 |
| `model.learning_rate` | 0.001–0.5 | 0.05 |
| `model.num_leaves` | 4–512 | 64 |
| `model.quantiles` | sorted list (0,1) | [0.1, 0.5, 0.9] |
| `features.weather.latitude` | -90..90 | 55.75 |
| `features.weather.longitude` | -180..180 | 37.62 |
| `features.holidays.country` | RU,US,DE,FR,... | RU |
| `anomaly_detection.contamination` | 0.01–0.3 | 0.05 |
| `hpo.n_trials` | 1–500 | 30 |

## 9. Обучение модели — data_path

**Важно:** бэкенд НЕ принимает файл через multipart/form-data. Он читает данные по пути `data_path`.

```json
// POST /clients/{id}/train
{
  "data_path": "s3://sku-forecasting/my-company/raw/sales.parquet"
}
```

### Варианты data_path

| Формат | Пример | Когда использовать |
|--------|--------|-------------------|
| S3 URI | `s3://bucket/client/raw/data.parquet` | Production (STORAGE_BACKEND=s3) |
| Локальный путь | `/opt/sku-data/my-company/sales.parquet` | Development (STORAGE_BACKEND=local) |

### Формат файла данных

```
date,sku,sales[,price,promo,stock]
2024-01-01,APPLE-001,100,45.5,0,500
2024-01-02,APPLE-001,115,45.5,1,450
...
```

- Минимум 30 строк на SKU (иначе cold start)
- `max_missing_ratio` = 0.10 (не более 10% пропусков)
- Parquet предпочтительнее CSV для больших файлов

### Статусы задания (rq)

| Статус | Значение |
|--------|----------|
| `queued` | В очереди Redis |
| `started` | Воркер обрабатывает |
| `finished` | Успешно завершено |
| `failed` | Ошибка |
| `unknown` | Redis недоступен или job не найден |

## 10. Формат истории для прогнозов

```json
// POST /clients/{id}/predict
{
  "sku": "APPLE-001",
  "horizon": 14,
  "history": [
    { "date": "2024-01-01", "sales": 100, "price": 45.5, "promo": 0, "stock": 500 },
    { "date": "2024-01-02", "sales": 115, "price": 45.5, "promo": 1, "stock": 450 },
    ... (минимум 30 строк)
  ]
}
```

### Ответ

```json
{
  "sku": "APPLE-001",
  "client_id": "my-company",
  "forecast": [112.3, 118.7, 105.1, ...],
  "forecast_dates": ["2024-02-01", "2024-02-02", "2024-02-03", ...],
  "horizon": 14,
  "model_source": "primary"   // primary | fallback | zero
}
```

`model_source`:
- `primary` — основная обученная модель
- `fallback` — резервная модель (если primary упала)
- `zero` — нулевой прогноз (нет ни одной модели)

## 11. Типичные ошибки и решения

### CORS: "No 'Access-Control-Allow-Origin' header"

**Причина:** CORS не настроен на бэкенде  
**Решение:** Добавить `CORSMiddleware` в `main.py` (см. раздел 3)

### 401 Unauthorized

**Причина 1:** Неверный `API_KEY`  
**Проверка:** `echo $API_KEY` на сервере бэкенда  
**Решение:** Использовать тот же ключ в поле "Секретный ключ" на фронте

**Причина 2:** JWT истёк (по умолчанию 60 минут)  
**Решение:** Повторный вход. Увеличить `JWT_EXPIRE_MINUTES` в `.env` бэкенда

### 422 Validation Error при PUT /config

**Причина:** Значение вне допустимого диапазона  
**Пример:** `model.horizon: 100` → ошибка (макс 90)  
**Ответ бэкенда содержит:** `detail: "Config validation failed: model.horizon=100 must be in [1, 90]"`

### 404 при POST /train

**Причина:** Модель ещё не обучена, predict вернёт 404  
**Решение:** Сначала обучить через POST /train, дождаться `status: finished`

### История слишком короткая (422)

**Причина:** `history` содержит менее 30 строк  
**Текст ошибки:** `min_length` validation error  
**Решение:** Передавать минимум 30 записей

### Задание `unknown` в /jobs/{id}

**Причина 1:** Redis недоступен — задание выполнилось синхронно, job_id = null  
**Причина 2:** TTL результата истёк (24 часа)  
**Решение:** Проверить `job_id` в ответе `/train` (может быть `null`)

### Фронт показывает старые данные

**Причина:** React Query кэш  
**Решение:** Хард-рефреш (Ctrl+Shift+R) или инвалидировать через queryClient

## Быстрый тест подключения

```bash
# 1. Проверить доступность бэкенда
curl https://api.yourdomain.com/health

# 2. Получить JWT
curl -X POST https://api.yourdomain.com/auth/token \
  -H "Content-Type: application/json" \
  -d '{"client_id": "test-client", "secret": "YOUR_API_KEY"}'

# 3. Проверить конфиг клиента
curl https://api.yourdomain.com/clients/test-client/config \
  -H "Authorization: Bearer YOUR_JWT_TOKEN"

# 4. Проверить CORS (с фронтенд-домена, в DevTools браузера)
fetch('https://api.yourdomain.com/health')
  .then(r => r.json())
  .then(console.log)
```
